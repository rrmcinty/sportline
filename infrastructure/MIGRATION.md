# Migration to CDK

This project has been migrated from bash scripts to AWS CDK for infrastructure management.

## What Changed

### Before (Bash Scripts)
```bash
./infrastructure/setup-s3.sh
./infrastructure/deploy-lambda.sh
```

### After (AWS CDK)
```bash
npm run cdk:deploy
```

## Benefits

1. **Type Safety** - Infrastructure is TypeScript, catch errors at compile time
2. **Better IDE Support** - IntelliSense for AWS resources
3. **Testable** - Can unit test infrastructure code
4. **Declarative** - Single source of truth for all resources
5. **Diff Before Deploy** - See exactly what will change with `npm run cdk:diff`
6. **Automatic IAM Roles** - CDK generates least-privilege roles automatically

## Old Scripts

The old bash scripts have been renamed to:
- `setup-s3.sh.deprecated`
- `deploy-lambda.sh.deprecated`

These are kept for reference but should not be used.

## New Commands

| Old | New |
|-----|-----|
| `./infrastructure/setup-s3.sh` | Handled by CDK |
| `./infrastructure/deploy-lambda.sh` | `npm run cdk:deploy` |
| Manual IAM role creation | Auto-generated by CDK |

## Migration Steps

If you already have the old bash-deployed infrastructure:

1. **Backup your data**
   ```bash
   aws s3 sync s3://sportline-data-$(whoami) /tmp/backup
   ```

2. **Delete old resources manually**
   ```bash
   # Delete old Lambda functions
   aws lambda delete-function --function-name Sportline-Update-$(whoami)
   aws lambda delete-function --function-name Sportline-Dashboard-$(whoami)

   # Delete EventBridge rule
   aws events remove-targets --rule Sportline-DailyUpdate-$(whoami) --ids 1
   aws events delete-rule --name Sportline-DailyUpdate-$(whoami)

   # Delete IAM role
   aws iam delete-role-policy --role-name Sportline-LambdaRole-$(whoami) --policy-name SportlineAccess
   aws iam detach-role-policy --role-name Sportline-LambdaRole-$(whoami) \
     --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
   aws iam delete-role --role-name Sportline-LambdaRole-$(whoami)
   ```

3. **Keep S3 bucket** (or delete and recreate)
   - Option A: Keep existing bucket, CDK will manage it going forward
   - Option B: Delete and let CDK create a new one

4. **Deploy with CDK**
   ```bash
   npm run all
   ```

5. **Verify**
   ```bash
   npm run cdk:diff
   ```

That's it! CDK now manages everything.
