# Sportline Cloud Infrastructure (AWS CDK)

Mobile dashboard for Sportline betting recommendations using AWS CDK with TypeScript.

## Architecture

```
Local Mac                         AWS Cloud (CDK Stack)           Mobile
┌──────────────┐           ┌───────────────────────────┐      ┌──────────────────┐
│ CLI Commands │──sync────▶│ S3 Bucket                 │      │ Mobile Browser   │
│ npm run sync │           │ • Models                  │      │ View recs        │
└──────────────┘           │ • Features                │      │ Filter/sort      │
                           │ • Daily recs (2-day TTL)  │      │ Pull to refresh  │
                           └───────────────────────────┘      └──────────────────┘
                                     │                                  │
                                     ▼                                  ▼
                           ┌───────────────────────────┐      ┌──────────────────┐
                           │ Update Lambda             │      │ Dashboard Lambda │
                           │ Daily 8am EST             │      │ Function URL     │
                           │ • Fetch odds from ESPN    │      │ (Public HTTPS)   │
                           │ • Run predictions         │      └──────────────────┘
                           │ • Write recs.json to S3   │
                           └───────────────────────────┘
                                     ▲
                           ┌───────────────────────────┐
                           │ EventBridge Rule          │
                           │ Cron: 0 13 * * ? *        │
                           └───────────────────────────┘
```

**Total: ~$0.02-0.50/month**

## Why CDK?

- ✅ **TypeScript everywhere** - Infrastructure, Lambdas, and frontend all in TypeScript
- ✅ **Type safety** - Catch errors at compile time
- ✅ **Better IDE support** - IntelliSense for AWS resources
- ✅ **Testable** - Unit test your infrastructure
- ✅ **Composable** - Reusable constructs
- ✅ **No bash scripts** - Infrastructure as code

## Setup

### Prerequisites

- AWS CLI configured (`aws configure`)
- Node.js 20+
- Existing sportline data (run local pipeline first)

### One-Command Setup

**Dev environment (uses your username):**
```bash
npm run all
```

**Production environment:**
```bash
npm run all:prod
```

This will:
1. Install all dependencies (root + infrastructure + lambdas)
2. Build TypeScript (main project + CDK + lambdas)
3. Sync models/features to S3
4. Deploy CDK stack (S3, Lambdas, EventBridge)
5. Output dashboard URL

### Manual Setup

If you want to run steps individually:

```bash
# 1. Install dependencies
npm ci                    # Root project
npm run cdk:install       # CDK infrastructure

# 2. Build everything
npm run build             # Main project
npm run lambda:build      # Lambda functions

# 3. Sync data to S3
npm run sync

# 4. Deploy CDK stack
npm run cdk:deploy        # Dev
npm run cdk:deploy:prod   # Production
```

## Daily Workflow

The system updates automatically at 8am EST via EventBridge. When you want to refresh team stats or models:

```bash
# Update local data
npm run ingest:sports:json
npm run import:nba:full
npm run import:ncaam:full
npm run import:nhl:full

# Sync to cloud
npm run sync              # Dev
ENV=prod npm run sync     # Production
```

## Stack Resources

The CDK stack creates:

| Resource | Name Pattern | Description |
|----------|--------------|-------------|
| **S3 Bucket** | `sportline-data-{env}` | Stores models, features, recommendations |
| **Update Lambda** | `Sportline-Update-{env}` | Fetches odds, runs predictions (5min timeout) |
| **Dashboard Lambda** | `Sportline-Dashboard-{env}` | Serves mobile UI (30s timeout) |
| **EventBridge Rule** | `Sportline-DailyUpdate-{env}` | Triggers Update Lambda daily at 8am EST |
| **IAM Roles** | Auto-generated by CDK | Least-privilege permissions |

## Environments

CDK supports multiple environments using stack naming:

```bash
# Dev (default - uses your username)
npm run cdk:deploy
# Creates: SportlineStack-ryanmcintyre

# Production
npm run cdk:deploy:prod
# Creates: SportlineStack-prod

# Custom environment
cd infrastructure && npm run cdk deploy -- -c env=staging
# Creates: SportlineStack-staging
```

## Troubleshooting

### Lambda can't find models in S3

Check bucket contents:
```bash
aws s3 ls s3://sportline-data-$(whoami)/models/ --recursive
```

If empty, run:
```bash
npm run sync
```

### Dashboard shows "Failed to load recommendations"

Check if Update Lambda has run:
```bash
aws s3 ls s3://sportline-data-$(whoami)/daily/
```

If no `recs.json`, manually invoke:
```bash
aws lambda invoke \
  --function-name Sportline-Update-$(whoami) \
  /tmp/out.json
```

### CDK deployment fails

Check CloudFormation events:
```bash
aws cloudformation describe-stack-events \
  --stack-name SportlineStack-$(whoami) \
  --max-items 10
```

View CDK diff to see what will change:
```bash
npm run cdk:diff
```

### Lambda build errors

Clean and rebuild:
```bash
cd lambda/update && npm run clean && npm install && npm run build
cd ../dashboard && npm run clean && npm install && npm run build
```

## Cleanup

To remove all cloud resources:

```bash
# Delete entire stack (dev)
npm run cdk:destroy

# Delete production stack
cd infrastructure && npm run cdk destroy -- -c env=prod

# Empty and delete S3 bucket manually if needed
aws s3 rm s3://sportline-data-$(whoami) --recursive
aws s3 rb s3://sportline-data-$(whoami)
```

## Why Not SAM or Serverless Framework?

- **SAM**: YAML-based, not type-safe
- **Serverless Framework**: Third-party, not AWS-native
- **CDK**: TypeScript, type-safe, AWS-native, best for projects already in TypeScript
